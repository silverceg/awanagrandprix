# 어와나 그랑프리

## 예선은 수동 편성, 이후는 자동 편성

1. 어와나 40명 / 일반부 18명을 부문별로 등록합니다.
2. **수동 조 편성하기 →**를 누릅니다. 선수끼리 자리를 바꾸거나 **빈 레인**을 선택할 수 있습니다. 빈 레인을 선택하면 해당 선수부터 뒤로 순서대로 이동하고 마지막 조가 꽉 차면 새 조가 자동으로 생깁니다. 기존 빈 레인은 유지됩니다. **+ 조 추가**로 직접 조를 늘릴 수도 있습니다. 미배치 선수가 남으면 저장되지 않습니다. **번호순 자동 편성**은 스티커 번호순으로 4명씩 다시 배치하며, 이후 수동으로 조정할 수 있습니다.
3. **이 편성으로 예선 시작**을 누르면 확정한 순서로 시작합니다. 경기 전에는 **조 편성 저장**으로 조정할 수 있습니다. 첫 기록 입력 후에는 변경할 수 없습니다.
4. 예선 종료 후 최고 기록으로 진출자를 선발하고, 이전 조·1차 레인 출전순에서 탈락자를 제외해 4명씩 자동 편성합니다. 16명은 4개 조, 8명은 2개 조, 결승은 1개 조입니다.

## 명단·사진을 나중에 보완하기

1. 어와나 또는 일반부를 고르고 **이름 등록 +**에서 이름만 입력합니다. 여러 명은 **엑셀 명단 한 번에 붙여넣기**에서 엑셀 셀을 복사해 붙여넣습니다. 이름 열만 복사해도 되고, 번호 / 이름 / 자동차 이름 열을 함께 복사해도 됩니다. **붙여넣은 명단 확인** 후 **명단 한 번에 추가**를 누르세요.
2. 번호를 비우면 임시 번호가 자동 부여됩니다. **참가자 명단 → 정보·사진 수정**에서 실제 스티커 번호, 이름, 자동차 이름을 수정합니다. 같은 부문 안에서는 번호를 중복할 수 없습니다.
3. **선수 사진 선택 / 자동차 사진 선택**에서 JPG·PNG·WebP(입력 파일당 20MB 이하)를 골라 미리보기를 확인하고 **정보·사진 저장**을 누릅니다. 사진이 없어도 저장됩니다.
4. 사진은 브라우저에서 최대 512px JPEG로 축소한 뒤 서버 SQLite에 저장됩니다. 선수 사진은 1:1 액자 안에, 자동차는 전체 모습이 보이게 표시됩니다. 사진 지우기는 저장 후 반영됩니다.
5. 경기 시작 뒤에도 개인 정보를 수정할 수 있으며 기존 조·기록 연결은 유지합니다. 참가자 추가·삭제는 경기 시작 전에만 가능합니다.

## 다른 노트북으로 접속하거나 서버를 옮기기

- **같은 서버에 접속:** 서버 노트북을 켠 채 같은 네트워크에서 `http://서버IP:3000/host`로 접속하면 기존 명단·사진·기록을 사용합니다. 각 노트북의 `localhost`는 서로 다른 컴퓨터입니다.
- **서버 자체를 바꾸기:** 원래 호스트에서 **명단·사진·모든 기록 백업 ↓**를 다운로드합니다. 새 노트북에서 이 프로그램을 실행하고 **다른 노트북에서 사용 · 명단과 사진 백업 / 복원**을 펼쳐 JSON 파일 선택 → 확인 문구 **백업 복원** → **백업 가져오기**를 누릅니다.
- 복원은 두 부문 전체를 교체합니다. 교체 직전 데이터는 자동 백업하고, 검증·백업에 실패하면 교체하지 않습니다. 기존 버전의 사진 없는 전체 JSON 백업도 지원합니다. 사진 포함 백업도 100MB 이하입니다.
- 무료 로컬 운영은 같은 `data` 폴더를 유지하면 재시작 후에도 남습니다. Render 무료 서버의 임시 디스크를 영구 저장소로 바꾸는 기능은 아닙니다. 서버 간 자동 동기화가 아니라 같은 서버 접속 또는 백업 이동 방식입니다.

## 전체 실시간 순위 화면

- `/leaderboard`: 어와나 예선 동안 호스트가 TV에 표시한 부문을 따라갑니다. 어와나 16강부터는 어와나와 일반부의 현재 라운드 순위를 좌우에 함께 표시합니다. 진행자 상단 **전체 순위 ↗**로 열 수 있습니다.
- `/leaderboard?division=awana`: 어와나 전용. `/leaderboard?division=open`: 일반부 전용.
- 두 번의 기록 입력이 끝난 참가자만 이름과 기록이 나타납니다. 진행 전에는 이름 없는 빈칸입니다. 두 번 모두 DNF이면 순위 번호 없이 미완주로 표시합니다.
- 어와나 40명 예선 → 종료 시 빈 16칸 → 빈 8칸 → 빈 4칸. 일반부 18명 예선 → 종료 시 빈 8칸 → 빈 4칸. 결승 종료 시 최종 결과는 유지됩니다. 과거 라운드 기록은 호스트의 기록 보기에서 확인합니다.
- 어와나 예선 종료 후에는 왼쪽 어와나 빈 16칸, 오른쪽 일반부 18칸이 함께 보입니다. 일반부 탭에서 수동 편성으로 예선을 시작하면 일반부에 진행 중 표시가 붙습니다. 일반부 예선 종료 시 오른쪽만 빈 8칸으로 바뀝니다.
- `/leaderboard?division=both`는 처음부터 두 부문을 함께 표시합니다. 부문 고정 링크는 계속 한 부문만 보여줍니다.
- 16:9 TV에 맞추며 40명은 세 열에 모두 표시합니다. 1·2·3위는 위쪽에서 크게 강조합니다. 기존 경기 TV의 오른쪽 순위는 1열을 유지합니다.


## 창 맞춤과 리허설 기록 초기화

- TV는 전체 판을 16:9로 유지해 창 안에 맞춥니다. 가로로 긴 창은 양옆에 여백이 생기며, 제목·이름·사진도 판 크기에 맞춰 줄어듭니다. 사진은 여백 있는 1:1 액자형입니다.
- 적용하려면 실행 창에서 Ctrl+C 후 `어와나-시작.cmd`를 다시 실행하고 진행자·TV 화면을 새로고침합니다.
- 리허설이 끝나면 진행자 화면 맨 아래 **리허설 종료 · 경기 기록 초기화**를 엽니다. 확인 문구에 `기록 초기화`를 입력하고 **두 부문 경기 기록 초기화**를 누릅니다.
- 어와나·일반부의 모든 라운드, 조, 주행·재경기 기록과 순위를 초기화합니다. 참가자, 스티커 번호, 자동차 이름, 사진 정보와 행사 이름은 유지합니다. 이후 각 부문에서 예선을 다시 시작하세요. 예선은 수동으로 다시 편성합니다.
- 초기화 전 데이터는 `data/rehearsal-backups/before-reset-*.json`에 자동 백업되며, 백업 실패 시 초기화하지 않습니다. 메뉴의 **백업 JSON 다운로드**는 가장 최근 백업을 제공합니다. 자동 백업은 현재 데이터를 덮어쓰지 않으며, 진행자 화면의 **다른 노트북에서 사용 · 명단과 사진 백업 / 복원**에서 이 JSON을 다시 가져올 수 있습니다.
- 현재 데이터 자체는 프로그램 업데이트로 초기화되지 않습니다. 초기화 버튼을 직접 실행한 경우에만 처리됩니다. 자세한 설명은 운영 매뉴얼 6쪽을 참고하세요.

4레인 수동 스톱워치 경기용 웹 대시보드입니다. 호스트 노트북에서 기록을 입력하고, TV에 연결한 다른 노트북에는 관객 전용 화면을 표시합니다. 서버는 Render 또는 로컬 노트북에서 실행합니다.

**순위는 두 기록 중 더 빠른 기록 하나로 결정합니다. 평균을 사용하지 않습니다.**

## 가장 먼저

- GitHub 저장소 이름은 **awana-grand-prix**를 권장합니다. 기존 **biblebattle** 프로젝트와 별도로 만드세요.
- 이 폴더의 **내용물**을 저장소 최상위에 올립니다. `package.json`, `server.js`, `render.yaml`이 첫 화면에 보여야 합니다.
- Render에는 **Web Service**로 배포하세요. Static Site로 배포하면 서버와 DB가 동작하지 않습니다.
- 경기 기록 보존에는 **유료 Web Service + Persistent Disk**가 필요합니다. 기본 파일 시스템이나 무료 서비스만으로는 재시작·재배포 후 기록이 보존되지 않습니다.
- 프로젝트에는 실제 참가자, 비밀번호, 경기 DB가 들어 있지 않습니다. 처음 실행하면 빈 대회가 생성됩니다.

## 로컬 Windows에서 실행

1. [Node.js 공식 사이트](https://nodejs.org/)에서 **Node.js 24.x**를 설치합니다. 이 프로젝트는 Node 24의 내장 SQLite를 사용합니다. 별도 DB 설치나 외부 npm 의존성은 없습니다.
2. `F:\awana` 폴더에서 PowerShell을 열고 아래 명령을 순서대로 실행합니다.

```powershell
cd F:\awana
Copy-Item .env.example .env
notepad .env
```

3. 비밀번호 없이 쓰려면 `HOST_PIN=`을 빈 값으로 둡니다. 비밀번호가 필요하면 8자 이상으로 설정하세요. 비밀번호가 없으면 주소를 아는 누구나 진행자 화면에서 기록을 수정할 수 있습니다.
4. 아래 명령을 실행합니다. PowerShell 실행 정책 문제를 피하도록 `npm.cmd`를 사용합니다.

```powershell
npm.cmd ci
npm.cmd start
```

5. 진행자: [http://localhost:3000/host](http://localhost:3000/host), 관객: [http://localhost:3000/tv](http://localhost:3000/tv).
6. 서버 창을 닫으면 접속이 끊깁니다. 정상 종료는 `Ctrl+C`입니다. 다시 시작하면 기존 기록이 복원됩니다.

같은 Wi-Fi의 TV 노트북에서는 **호스트 노트북의 LAN IP**로 접속합니다. 예를 들어 호스트 IP가 `192.168.0.10`이면 `http://192.168.0.10:3000/tv`입니다. TV 노트북에서 `localhost`를 쓰면 호스트에 연결되지 않습니다. Windows 방화벽의 Node.js **개인 네트워크** 허용 여부도 확인하세요. 공유기의 클라이언트 격리가 켜져 있으면 두 노트북 간 접속이 제한될 수 있습니다.

## GitHub에 직접 업로드

1. GitHub에서 `New repository`를 눌러 `awana-grand-prix` 저장소를 만듭니다. 이름과 공개 범위는 직접 선택하세요.
2. `Add file → Upload files` 또는 빈 저장소의 `uploading an existing file`을 선택합니다.
3. 이 폴더 안의 파일과 `public`, `lib`, `scripts`, `test` 폴더를 함께 올립니다. **ZIP 자체를 올리면 배포되지 않습니다.** ZIP을 받았다면 먼저 압축을 푸세요.
4. `.gitignore`, `.env.example`, `.node-version`도 포함되었는지 확인합니다. Windows에서 숨김 파일 보기를 켜면 확인하기 쉽습니다.
5. `Commit changes`를 누릅니다. 저장소 첫 화면에 `package.json`이 있는지 확인하세요.
6. **`.env`, `data/`, `backups/`는 올리지 마세요.** 로컬 실행 후 수동으로 파일을 업로드할 때도 이 항목들을 제외해야 합니다. `.gitignore`는 웹 업로드를 자동으로 막아 주지 않습니다.

## Render 배포

자세한 설정은 [DEPLOYMENT.md](DEPLOYMENT.md)에 있습니다.

### 방법 A: Blueprint

1. Render에서 `New → Blueprint`를 선택하고 위 GitHub 저장소를 연결합니다.
2. 루트의 `render.yaml`을 사용합니다.
3. 기본은 비밀번호 없이 사용합니다. Render Environment에 기존 `HOST_PIN`이 있다면 삭제하거나 빈 값으로 저장하고 재배포하세요. 보호가 필요하면 8자 이상 값을 설정할 수 있습니다.
4. 유료 서비스와 디스크 구성을 확인한 뒤 직접 생성합니다. 이 파일을 만드는 것만으로 결제나 배포가 실행되지는 않습니다.
5. 배포 완료 후 `https://서비스주소.onrender.com/host`와 `/tv`를 각각 엽니다.

### 방법 B: Web Service 직접 설정

| 설정 | 값 |
| --- | --- |
| Language / Runtime | Node |
| Root Directory | 저장소 루트면 비워 둠 |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Instance Type | 영구 디스크를 연결할 수 있는 유료 플랜 |
| Node 버전 | `NODE_VERSION=24.20.0` |
| 진행자 비밀번호 | 선택 사항. HOST_PIN을 생략하거나 빈 값이면 로그인 없이 사용, 설정하면 8자 이상 |
| 환경 | `NODE_ENV=production` |
| 데이터 경로 | `DATA_DIR=/var/data` |
| Persistent Disk | Mount Path `/var/data`, Size `1 GB` |

`PORT`는 Render가 지정하므로 따로 고정하지 마세요. 서버는 `0.0.0.0`과 제공된 포트를 사용합니다. 단일 인스턴스로 운영하세요. 경기 중 코드 변경에 따른 재배포를 막기 위해 Blueprint의 자동 배포는 꺼 두었습니다.

## 경기 규칙과 운영 절차

### 1. 경기 전에

- 진행자 화면 접속(비밀번호를 설정한 경우 로그인) → 어와나/일반부 탭 선택 → 참가자 등록.
- 입력 예: `12,김하늘` 또는 `김하늘`. 차량 번호는 부문 안에서 중복될 수 없습니다. 동명이인은 차량 번호로 구분합니다.
- 참가자명은 관객 화면에 공개됩니다. 필요한 경우 별명이나 차량명으로 등록하세요.
- 명단·차량 번호를 확인한 뒤 수동 조 편성에서 배치하고 `이 편성으로 예선 시작`. 예선 시작 후 추가·삭제만 잠깁니다. 각 참가자의 이름·번호·자동차 이름·사진은 계속 수정할 수 있습니다.
- 어와나는 최소 16명, 일반부는 최소 8명이어야 시작할 수 있습니다. 부문별 최대 100명을 지원합니다.
- 초기 화면은 40명 10개 조, 18명 5개 조입니다. 번호순 자동 편성은 4명씩 묶어 18명을 4명 조 4개와 2명 조 1개로 배치합니다. 수동으로 빈 레인·조 추가를 사용해 인원을 조정할 수 있습니다. 빈 레인은 실제 화면에 표시됩니다.
- TV 노트북에서 `/tv`를 열고 전체 화면 버튼 또는 F11을 누릅니다. 진행자 비밀번호는 TV 노트북에 입력하지 않습니다.

### 2. 기록 입력

1. 진행자가 조와 1차 주행 선택 → `이 경기를 TV에 표시`.
2. 화면의 레인별 이름과 실제 자동차를 대조합니다.
3. 모든 스톱워치를 같은 출발 신호에 맞춰 시작하고, 담당 레인의 결승선 통과 시 정지합니다.
4. 기록을 **초 단위**로 입력합니다. 예: `3.42` 또는 `3.420`. 최대 소수점 3자리이며, 스톱워치가 0.01초 단위라면 표시된 값까지만 입력하세요.
5. 미완주는 해당 레인의 `미완주 DNF` 버튼을 누릅니다. 0초는 실제 경기 기록으로 저장할 수 없습니다.
6. `기록 저장` → 저장 완료 알림 확인 → `다음 주행`으로 이동.
7. 2차의 실제 레인 변경은 운영진이 진행합니다. 대시보드는 같은 선수 순서를 유지하므로 이름·스티커 번호를 확인하여 초를 입력합니다.
8. 2차 저장 후 다음 조로 이동합니다. 조 선택을 바꾼 것만으로 TV가 바뀌지는 않습니다. `이 경기를 TV에 표시` 또는 `다음 주행`을 사용하세요.

두 번의 기록이 `3.200`, `3.600`이면 순위 기록은 **3.200초**입니다. `DNF`, `3.450`이면 **3.450초**입니다. 두 번 모두 DNF이면 유효 순위가 없고 자동 진출 대상에서 제외합니다. 한 번만 입력했으면 두 번을 완료할 때까지 순위는 대기입니다.

### 3. 동점과 재경기

- 같은 최고 기록은 공동 순위로 표시합니다. 다른 주행의 느린 기록, 차량 번호, 등록 순서로 진출자를 결정하지 않습니다.
- 진출 기준 순위에서 최고 기록이 같으면 전원 진출합니다. 공동 16위가 2명이면 17명, 일반부 공동 8위가 2명이면 9명이 진출합니다. 다른 주행이나 기존 재경기 기록으로 진출 동점을 가르지 않습니다.
- 결승의 `동점자 재경기 입력`에서 각 참가자의 별도 기록과 사유를 저장합니다. 원래 두 기록은 보존됩니다.
- 결승에서는 같은 최고 기록인 참가자끼리 재경기 기록이 빠른 순서로 결정합니다. 재경기도 동점이면 해당 동점 경기를 다시 하고 대상자 기록을 모두 갱신하세요.
- 결승은 유효 기록을 가진 모든 동점자의 순위를 재경기로 확정해야 종료할 수 있습니다.
- **기본 1·2차 기록을 변경하면 해당 라운드의 재경기 기록이 모두 초기화**됩니다. 동점 집단이 달라질 수 있기 때문입니다. 기본 기록을 먼저 확정한 뒤 재경기를 진행하세요.
- 재경기는 운영자가 동점자끼리 동일한 출발 조건과 합의한 레인으로 별도 진행하며, 일반 편성표에 추가되지 않습니다. 재경기 기록은 순위 표에 표시됩니다.

### 4. 라운드 종료

1. 완료 인원과 기록을 확인합니다. 미입력·유효 기록 인원 부족이 있으면 종료할 수 없습니다.
2. `예선 종료 및 다음 조 자동 편성` 등 종료 버튼을 누르고 확인합니다.
3. 어와나 예선은 상위 16명, 이후 8명, 4명으로 자동 등록합니다. 일반부는 8명, 4명입니다. **부문 전체 기록순**으로 선발하며 조별 1등만 뽑지 않습니다.
4. 새 라운드의 `scoreMs`는 **0**, 두 주행 기록은 **미입력(null)**, 재경기 기록은 미입력으로 생성됩니다. 0초가 우승 기록으로 처리되지 않습니다. 참가자 이름과 차량 번호는 유지됩니다.
5. `기록 보기` 메뉴에서 이전 라운드를 확인합니다. 종료된 라운드는 수정할 수 없습니다.
6. 결승 종료 후 관객 화면은 1~3위 시상 화면으로 바뀝니다. 4위를 포함한 전체 결과는 진행자 표와 CSV에서 확인합니다.

### 5. 공정한 수동 측정을 위한 운영 기준

각 레인에 고정된 기록 담당자를 두고, 출발 신호·결승선 판정·기록 자릿수를 통일하세요. 트랙 수평과 레인 상태를 먼저 점검하고 출발 장치 오작동은 기록 입력 전 재경기 여부를 결정하세요. 실제 레인 배치는 운영진이 정하며 시스템에서 자동 변경하지 않습니다. 따라서 레인별 속도 차이 또는 수동 측정자의 반응 차이를 완전히 없애지는 못합니다. 사전 테스트로 트랙과 측정 조건을 맞추는 것이 필요합니다.

## 백업, 복원, 새 행사

- 화면의 `기록 CSV`는 엑셀에서 열 수 있는 UTF-8 BOM 파일입니다.
- `전체 기록 JSON`에는 명단, 선수·자동차 사진, 모든 라운드의 경기 기록이 포함됩니다. 다른 서버의 진행자 화면에서 가져올 수 있습니다. 변경 내역·내부 스냅샷까지 보관하려면 SQLite 백업을 사용하세요.
- 실제 복원용 DB 백업은 서버 폴더에서 아래 명령으로 만듭니다. SQLite 온라인 백업 API를 사용하므로 서버 실행 중에도 일관된 파일을 만듭니다.

```powershell
npm.cmd run backup
```

백업은 `backups/awana-날짜.sqlite`에 생성됩니다. Render에서는 Shell에서 실행한 후 파일을 별도로 다운로드하세요. `backups/`는 기본 설정상 영구 디스크 밖이므로 재배포 전에 내려받아야 합니다. 화면에서 받는 CSV/JSON도 각 라운드 종료마다 별도로 보관하세요.

**DB 복원:** 서버를 정상 종료한 뒤 현재 `data` 폴더 전체를 다른 이름으로 보관합니다. 새 `data` 폴더를 만들고 복원할 백업 파일을 `awana.sqlite`라는 이름으로 넣은 뒤 재시작합니다. 이전 `-wal`, `-shm` 파일과 복원 파일을 섞지 마세요. Render라면 설정된 `DATA_DIR`와 동일한 위치에서 작업합니다. 영구 디스크 파일을 변경하는 동안 서버가 실행되지 않도록 서비스 운영 절차에 따라 중지해야 합니다.

**새 행사:** 기존 기록을 백업한 뒤 `.env`의 `DATA_DIR`를 새 빈 폴더 경로(예: `./data-event-2`)로 바꾸고 재시작합니다. 기존 폴더는 그대로 남습니다. Render에서는 `/var/data/event-2`처럼 영구 디스크 아래의 새 경로를 사용하세요. 새 폴더도 GitHub 업로드에서 제외하세요.

매 변경 전 DB에 내부 스냅샷이 저장되지만, 이를 되돌리는 운영자 UI는 제공하지 않습니다. 대회 종료는 반드시 기록을 검토한 뒤 누르세요.

## 점검 및 문제 해결

- 테스트: `npm.cmd test` (Render/Linux는 `npm test`). 자동 테스트는 임시 DB를 사용하며 실제 경기 DB를 수정하지 않습니다.
- 비밀번호를 설정했을 때 로그인 오류: `HOST_PIN`이 8자 이상인지 확인합니다. 10회 실패하면 10분간 재시도가 제한됩니다.
- 비밀번호를 설정한 경우 재시작 후에는 다시 로그인해야 합니다. 경기 기록은 유지되지만 로그인 세션은 서버 메모리에 있어 초기화됩니다.
- 로컬 HTTP에서는 `NODE_ENV=development`를 사용합니다. `production`은 HTTPS 전용 로그인 쿠키를 사용합니다.
- 접속이 끊기면 화면의 마지막 데이터가 그대로 남고 빨간색 연결 안내가 표시됩니다. 연결이 복구되면 최신 상태를 다시 받습니다. **오프라인 상태에서 입력한 기록은 서버에 저장되지 않으므로 저장 완료를 확인하세요.**
- 다른 진행자 창에서 저장하면 기존 화면의 입력을 자동으로 덮어쓰지 않습니다. 충돌 안내가 나오면 내용을 확인한 뒤 최신 화면을 불러와 다시 입력하세요.
- 화면 주소를 `file://`로 직접 열지 말고 서버 주소로 접속하세요.
- DB는 단일 서버 인스턴스용입니다. 멀티 인스턴스 수평 확장은 지원하지 않습니다.

배포 기준은 2026-10-11 확인한 [Render Node 서비스 안내](https://render.com/docs/deploy-node-express-app), [영구 디스크 안내](https://render.com/docs/disks), [Blueprint 명세](https://render.com/docs/blueprint-spec)에 따릅니다.


## 자동차 이름

- 참가자 등록 시 `차량번호,이름,자동차이름` 형식으로 입력할 수 있습니다. 예: `1,김하늘,번개호`.
- 기존 `이름` 또는 `차량번호,이름` 형식도 지원하며 자동차 이름은 선택 입력입니다.
- 진행자 화면의 **참가자 명단 → 정보·사진 수정**에서 자동차 이름과 사진을 저장합니다. 경기 시작 후에도 입력·수정할 수 있습니다.
- 최대 24자. TV 카드 아래쪽에서 잘 보이도록 짧은 이름을 권장합니다. 긴 이름은 말줄임 표시됩니다.
- 이름이 없으면 **자동차 이름 미등록**으로 표시됩니다. 기존 DB도 그대로 사용할 수 있습니다.
- 자동차 이름은 SQLite와 JSON/CSV 내보내기에 저장됩니다. 변경해도 주행 기록·편성은 바뀌지 않습니다.


## 비밀번호 없이 사용하기

기본 설정은 비밀번호가 없습니다. `/host`를 열면 바로 참가 등록·기록 입력 화면으로 들어갑니다. Render의 Environment에서 `HOST_PIN`을 삭제하거나 비워두고 재배포하세요. 로컬 `.env`에도 기존 값이 있다면 비워야 합니다. 비밀번호를 생략하면 공개 주소에 접근할 수 있는 누구나 기록 변경·내보내기가 가능합니다.

이 변경은 로그인 방식에만 해당하며 무료 Render의 기록 보존 제한을 해결하지 않습니다. 현재 DB는 SQLite이고 외부 무료 DB 연동은 아직 포함하지 않습니다.

## 두 번 클릭으로 현장 실행

Windows에서는 `어와나-시작.cmd`를 두 번 클릭합니다. Node.js 24가 필요하며 별도 npm 설치는 필요하지 않습니다. 진행자는 http://localhost:3000/host, TV는 실행 창에 표시되는 http://호스트주소:3000/tv 를 엽니다. 두 노트북은 같은 공유기/Wi-Fi에 연결합니다.

이 실행기는 비밀번호 없이, 포트 3000과 프로젝트의 data 폴더를 사용하며 .env나 Render 설정에 영향을 받지 않습니다. 종료는 Ctrl+C이며, 종료 후 data 폴더를 USB에 복사하여 백업할 수 있습니다. 자세한 안내는 로컬사용법.txt를 참고하세요.

## 50인치 TV와 부문별 진행 순서

상세 안내는 **어와나-그랑프리-운영매뉴얼.pdf**를 참고하세요.

- 일반적인 16:9 TV 기준이며 1920×1080 브라우저에서 검증했습니다. 50인치는 크기이므로 해상도는 TV 권장 설정을 사용하세요. 브라우저 확대 100%, F11 전체 화면을 권장합니다.
- 실시간 순위는 한 열입니다. 1위, 2위, 3위 순서로 카드와 이름·기록이 작아지고, 4위 이하는 같은 크기입니다. 기존 `/tv`의 경기 화면은 상위 8명, 순위 모드는 8명씩 8초마다 전환합니다. 새 `/leaderboard`는 40명 전체를 한 번에 보여주는 별도 화면입니다.
- 어와나 40명 예선을 마치고 **예선 종료 및 다음 조 자동 편성**을 누르면 상위 16명이 준준결승 4개 조로 자동 등록됩니다. 예선 기록은 보존되며 새 주행 기록은 미입력, 점수는 0으로 초기화됩니다.
- 다음으로 **일반부** 탭에서 18명을 확인하고 **수동 조 편성하기 →**를 눌러 배치한 뒤 **이 편성으로 예선 시작**을 누릅니다. 일반부 예선 종료 시 상위 8명, 준결승 2개 조가 자동 생성됩니다.
- 이후 어와나 탭으로 돌아와 준비된 준준결승의 조·주행을 확인하고 **이 경기를 TV에 표시**를 누릅니다. 부문 탭만 바꾸면 TV는 그대로입니다.
- 어와나 16→8→4, 일반부 8→4의 매 라운드에서 진출자와 조가 자동 등록됩니다. 부문 전체 상위 기록으로 진출자를 선발한 뒤, 이전 조·1차 레인 출전순에서 탈락자만 제외하고 앞에서부터 4명씩 묶습니다. 순위순이나 번호순으로 재정렬하지 않습니다.
- 두 부문은 독립적으로 저장됩니다. 일반부 진행 중에도 어와나 16강과 예선 기록은 유지됩니다. 종료 전 모든 참가자의 두 기록 입력이 필요합니다. 진출선 동점자는 함께 진출합니다.


## 당일 번호 스티커와 순서 유지

- 당일 자동차에 붙인 스티커 번호를 차량 번호로 입력합니다. 예: `12,김하늘,번개호`. 부문 안에서 번호는 중복될 수 없습니다.
- 번호는 예선부터 결승까지 동일하며, 화면의 `#12`와 실제 스티커를 맞춰 확인합니다. 순위·조 번호·레인 번호와는 다른 고정 식별 번호입니다.
- 다음 라운드는 이전 조 번호 순서, 각 조의 1차 레인 순서에서 탈락자를 제외하고 4명씩 편성합니다. 스티커를 다시 붙일 필요가 없습니다.
- 이번 변경은 서버를 재시작한 뒤 라운드 종료로 새로 생성하는 조부터 적용됩니다. 이미 생성된 조와 저장된 기록은 자동 변경하지 않습니다.

## 자동 밀림과 동점 진출 업데이트

- 1조 4레인을 비우면 4번부터 다음 자리로 순서대로 이동합니다. 40명 모두 배치된 상태에서 11조가 자동 생성됩니다. 변경 후 조 편성을 저장하세요.
- 다음 라운드는 실제 진출 인원으로 편성합니다. 17명은 4·4·4·4·1명, 9명은 4·4·1명입니다. 순위표 빈칸 수도 실제 인원에 맞춥니다. 첫 기록 입력 전 수동 조정할 수 있습니다.
- 결승 진출 기준 동점도 모두 진출합니다. 결승 경기 자체의 최종 순위 동점은 기존처럼 재경기로 확정합니다.
- TV 경기 카드의 장식 응원 문구를 제거하고 아래 자동차 사진·이름 영역을 확대했습니다. 2차 화면의 1차 기록은 유지합니다.
