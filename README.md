# 어와나 그랑프리

4레인 수동 스톱워치 경기용 웹 대시보드입니다. 호스트 노트북에서 기록을 입력하고, TV에 연결한 다른 노트북에는 관객 전용 화면을 표시합니다. 서버는 Render 또는 로컬 노트북에서 실행합니다.

**순위는 두 기록 중 더 빠른 기록 하나로 결정합니다. 평균을 사용하지 않습니다.**

## 가장 먼저

- GitHub 저장소 이름은 **awana-grand-prix**를 권장합니다. 기존 **biblebattle** 프로젝트와 별도로 만드세요.
- 이 폴더의 **내용물**을 저장소 최상위에 올립니다. `package.json`, `server.js`, `render.yaml`이 첫 화면에 보여야 합니다.
- Render에는 **Web Service**로 배포하세요. Static Site로 배포하면 서버와 DB가 동작하지 않습니다.
- 경기 기록 보존에는 **유료 Web Service + Persistent Disk**가 필요합니다. 기본 파일 시스템이나 무료 서비스만으로는 재시작·재배포 후 기록이 보존되지 않습니다.
- 프로젝트에는 실제 참가자, 비밀번호, 경기 DB가 들어 있지 않습니다. 처음 실행하면 빈 대회가 생성됩니다.

## 포함된 기능

| 항목 | 동작 |
| --- | --- |
| 어와나 | 권장 40~45명 → 예선 → 16명 준준결승 → 8명 준결승 → 4명 결승 |
| 일반부 | 권장 18~20명 → 예선 → 8명 준결승 → 4명 결승 |
| 참가 등록 | 한 줄에 한 명, 차량 번호 자동 부여 또는 직접 지정, 시작 전 삭제 가능 |
| 경기 편성 | 최대 4명씩 균등 편성, 예선은 무작위, 이후는 이전 순위에 따른 스네이크 배정 |
| 주행 횟수 | 같은 조가 두 번 달림. 2차 레인은 1→3, 2→4, 3→1, 4→2 |
| 순위 | 두 번 모두 입력한 뒤 유효 기록 중 최솟값으로 계산, 작은 값 우선 |
| 다음 라운드 | 종료 버튼으로 진출자 자동 등록, 새 점수 0, 주행 기록 미입력 상태 |
| 이전 기록 | 종료된 라운드를 보존하고 화면·CSV·JSON에서 확인 |
| 관객 화면 | 4레인 현재 경기, 포스터형 메인 화면 + 오른쪽 8명 순위판, 전체 순위 자동 순환, 결승 시상 화면 |
| 실시간 연결 | SSE 자동 갱신·재연결, 끊김 상태 표시 |
| 데이터 | SQLite 트랜잭션·WAL, 모든 변경 이력 및 변경 전 스냅샷 저장 |
| 진행자 보호 | 비밀번호 로그인, 읽기 전용 관객, 동시 저장 충돌 차단 |

## 로컬 Windows에서 실행

1. [Node.js 공식 사이트](https://nodejs.org/)에서 **Node.js 24.x**를 설치합니다. 이 프로젝트는 Node 24의 내장 SQLite를 사용합니다. 별도 DB 설치나 외부 npm 의존성은 없습니다.
2. `F:\awana` 폴더에서 PowerShell을 열고 아래 명령을 순서대로 실행합니다.

```powershell
cd F:\awana
Copy-Item .env.example .env
notepad .env
```

3. 메모장에서 `HOST_PIN` 값을 **본인이 정한 8자 이상 비밀번호**로 바꾸고 저장합니다. 예제의 기본 문자열로는 서버가 시작되지 않습니다. 공백이나 `#`가 포함되면 값을 큰따옴표로 감싸세요.
4. 아래 명령을 실행합니다. PowerShell 실행 정책 문제를 피하도록 `npm.cmd`를 사용합니다.

```powershell
npm.cmd ci
npm.cmd start
```

5. 진행자: [http://localhost:3000/host](http://localhost:3000/host), 관객: [http://localhost:3000/tv](http://localhost:3000/tv).
6. 서버 창을 닫으면 접속이 끊깁니다. 정상 종료는 `Ctrl+C`입니다. 다시 시작하면 기존 기록이 복원됩니다.

같은 Wi-Fi의 TV 노트북에서는 **호스트 노트북의 LAN IP**로 접속합니다. 예를 들어 호스트 IP가 `192.168.0.10`이면 `http://192.168.0.10:3000/tv`입니다. TV 노트북에서 `localhost`를 쓰면 호스트에 연결되지 않습니다. Windows 방화벽의 Node.js **개인 네트워크** 허용 여부도 확인하세요. 공유기의 클라이언트 격리가 켜져 있으면 두 노트북 간 접속이 제한될 수 있습니다.

## GitHub에 직접 업로드

1. GitHub에서 `New repository`를 눌러 `awana-grand-prix` 저장소를 만듭니다. 이름과 공개 범위는 직접 선택하세요.
2. `Add file → Upload files` 또는 빈 저장소의 `uploading an existing file`을 선택합니다.
3. 이 폴더 안의 파일과 `public`, `lib`, `scripts`, `test` 폴더를 함께 올립니다. **ZIP 자체를 올리면 배포되지 않습니다.** ZIP을 받았다면 먼저 압축을 푸세요.
4. `.gitignore`, `.env.example`, `.node-version`도 포함되었는지 확인합니다. Windows에서 숨김 파일 보기를 켜면 확인하기 쉽습니다.
5. `Commit changes`를 누릅니다. 저장소 첫 화면에 `package.json`이 있는지 확인하세요.
6. **`.env`, `data/`, `backups/`는 올리지 마세요.** 로컬 실행 후 수동으로 파일을 업로드할 때도 이 항목들을 제외해야 합니다. `.gitignore`는 웹 업로드를 자동으로 막아 주지 않습니다.

## Render 배포

자세한 설정은 [DEPLOYMENT.md](DEPLOYMENT.md)에 있습니다.

### 방법 A: Blueprint

1. Render에서 `New → Blueprint`를 선택하고 위 GitHub 저장소를 연결합니다.
2. 루트의 `render.yaml`을 사용합니다.
3. 요청되는 `HOST_PIN`에 8자 이상 진행자 비밀번호를 입력합니다.
4. 유료 서비스와 디스크 구성을 확인한 뒤 직접 생성합니다. 이 파일을 만드는 것만으로 결제나 배포가 실행되지는 않습니다.
5. 배포 완료 후 `https://서비스주소.onrender.com/host`와 `/tv`를 각각 엽니다.

### 방법 B: Web Service 직접 설정

| 설정 | 값 |
| --- | --- |
| Language / Runtime | Node |
| Root Directory | 저장소 루트면 비워 둠 |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Instance Type | 영구 디스크를 연결할 수 있는 유료 플랜 |
| Node 버전 | `NODE_VERSION=24.20.0` |
| 진행자 비밀번호 | `HOST_PIN=본인이 정한 8자 이상 비밀번호` |
| 환경 | `NODE_ENV=production` |
| 데이터 경로 | `DATA_DIR=/var/data` |
| Persistent Disk | Mount Path `/var/data`, Size `1 GB` |

`PORT`는 Render가 지정하므로 따로 고정하지 마세요. 서버는 `0.0.0.0`과 제공된 포트를 사용합니다. 단일 인스턴스로 운영하세요. 경기 중 코드 변경에 따른 재배포를 막기 위해 Blueprint의 자동 배포는 꺼 두었습니다.

## 경기 규칙과 운영 절차

### 1. 경기 전에

- 진행자 화면 로그인 → 어와나/일반부 탭 선택 → 참가자 등록.
- 입력 예: `12,김하늘` 또는 `김하늘`. 차량 번호는 부문 안에서 중복될 수 없습니다. 동명이인은 차량 번호로 구분합니다.
- 참가자명은 관객 화면에 공개됩니다. 필요한 경우 별명이나 차량명으로 등록하세요.
- 명단·차량 번호를 확인한 뒤 `예선 시작`. 예선 시작 후 명단은 잠깁니다.
- 어와나는 최소 16명, 일반부는 최소 8명이어야 시작할 수 있습니다. 부문별 최대 100명을 지원합니다.
- 45명은 12개 조(4명 조 9개, 3명 조 3개), 18명은 5개 조(4명 조 3개, 3명 조 2개)로 나뉩니다. 빈 레인은 실제 화면에 표시됩니다.
- TV 노트북에서 `/tv`를 열고 전체 화면 버튼 또는 F11을 누릅니다. 진행자 비밀번호는 TV 노트북에 입력하지 않습니다.

### 2. 기록 입력

1. 진행자가 조와 1차 주행 선택 → `이 경기를 TV에 표시`.
2. 화면의 레인별 이름과 실제 자동차를 대조합니다.
3. 모든 스톱워치를 같은 출발 신호에 맞춰 시작하고, 담당 레인의 결승선 통과 시 정지합니다.
4. 기록을 **초 단위**로 입력합니다. 예: `3.42` 또는 `3.420`. 최대 소수점 3자리이며, 스톱워치가 0.01초 단위라면 표시된 값까지만 입력하세요.
5. 미완주는 해당 레인의 `미완주 DNF` 버튼을 누릅니다. 0초는 실제 경기 기록으로 저장할 수 없습니다.
6. `기록 저장` → 저장 완료 알림 확인 → `다음 주행`으로 이동.
7. 2차는 같은 참가자의 레인을 두 칸 옮깁니다. 레인 배치는 화면에 자동으로 반영됩니다.
8. 2차 저장 후 다음 조로 이동합니다. 조 선택을 바꾼 것만으로 TV가 바뀌지는 않습니다. `이 경기를 TV에 표시` 또는 `다음 주행`을 사용하세요.

두 번의 기록이 `3.200`, `3.600`이면 순위 기록은 **3.200초**입니다. `DNF`, `3.450`이면 **3.450초**입니다. 두 번 모두 DNF이면 유효 순위가 없고 자동 진출 대상에서 제외합니다. 한 번만 입력했으면 두 번을 완료할 때까지 순위는 대기입니다.

### 3. 동점과 재경기

- 같은 최고 기록은 공동 순위로 표시합니다. 다른 주행의 느린 기록, 차량 번호, 등록 순서로 진출자를 결정하지 않습니다.
- 진출선에 동점자가 걸리면 라운드 종료가 차단됩니다. 예를 들어 16위 경계에서 최고 기록이 같은 참가자 전원을 재경기시킵니다.
- `동점자 재경기 입력`에서 각 참가자의 별도 기록과 사유를 저장합니다. 원래 두 기록은 보존됩니다.
- 같은 최고 기록인 참가자끼리는 재경기 기록이 빠른 순서로 결정합니다. 재경기도 동점이면 해당 동점 경기를 다시 하고 대상자 기록을 모두 갱신하세요.
- 결승은 유효 기록을 가진 모든 동점자의 순위를 재경기로 확정해야 종료할 수 있습니다.
- **기본 1·2차 기록을 변경하면 해당 라운드의 재경기 기록이 모두 초기화**됩니다. 동점 집단이 달라질 수 있기 때문입니다. 기본 기록을 먼저 확정한 뒤 재경기를 진행하세요.
- 재경기는 운영자가 동점자끼리 동일한 출발 조건과 합의한 레인으로 별도 진행하며, 일반 편성표에 추가되지 않습니다. 재경기 기록은 순위 표에 표시됩니다.

### 4. 라운드 종료

1. 완료 인원과 기록을 확인합니다. 미입력·진출선 동점·진출 인원 부족이 있으면 종료할 수 없습니다.
2. `예선 종료 및 자동 진출` 등 종료 버튼을 누르고 확인합니다.
3. 어와나 예선은 상위 16명, 이후 8명, 4명으로 자동 등록합니다. 일반부는 8명, 4명입니다. **부문 전체 기록순**으로 선발하며 조별 1등만 뽑지 않습니다.
4. 새 라운드의 `scoreMs`는 **0**, 두 주행 기록은 **미입력(null)**, 재경기 기록은 미입력으로 생성됩니다. 0초가 우승 기록으로 처리되지 않습니다. 참가자 이름과 차량 번호는 유지됩니다.
5. `기록 보기` 메뉴에서 이전 라운드를 확인합니다. 종료된 라운드는 수정할 수 없습니다.
6. 결승 종료 후 관객 화면은 1~3위 시상 화면으로 바뀝니다. 4위를 포함한 전체 결과는 진행자 표와 CSV에서 확인합니다.

### 5. 공정한 수동 측정을 위한 운영 기준

각 레인에 고정된 기록 담당자를 두고, 출발 신호·결승선 판정·기록 자릿수를 통일하세요. 트랙 수평과 레인 상태를 먼저 점검하고 출발 장치 오작동은 기록 입력 전 재경기 여부를 결정하세요. 이 시스템의 두 번 주행은 **서로 다른 두 레인**을 사용하며 네 레인을 모두 경험하는 방식은 아닙니다. 따라서 레인별 속도 차이 또는 수동 측정자의 반응 차이를 완전히 없애지는 못합니다. 사전 테스트로 트랙과 측정 조건을 맞추는 것이 필요합니다.

## 백업, 복원, 새 행사

- 화면의 `기록 CSV`는 엑셀에서 열 수 있는 UTF-8 BOM 파일입니다.
- `전체 기록 JSON`에는 모든 라운드와 최근 변경 이력이 포함됩니다. 조회·보관용이며 화면에서 가져오는 기능은 없습니다.
- 실제 복원용 DB 백업은 서버 폴더에서 아래 명령으로 만듭니다. SQLite 온라인 백업 API를 사용하므로 서버 실행 중에도 일관된 파일을 만듭니다.

```powershell
npm.cmd run backup
```

백업은 `backups/awana-날짜.sqlite`에 생성됩니다. Render에서는 Shell에서 실행한 후 파일을 별도로 다운로드하세요. `backups/`는 기본 설정상 영구 디스크 밖이므로 재배포 전에 내려받아야 합니다. 화면에서 받는 CSV/JSON도 각 라운드 종료마다 별도로 보관하세요.

**DB 복원:** 서버를 정상 종료한 뒤 현재 `data` 폴더 전체를 다른 이름으로 보관합니다. 새 `data` 폴더를 만들고 복원할 백업 파일을 `awana.sqlite`라는 이름으로 넣은 뒤 재시작합니다. 이전 `-wal`, `-shm` 파일과 복원 파일을 섞지 마세요. Render라면 설정된 `DATA_DIR`와 동일한 위치에서 작업합니다. 영구 디스크 파일을 변경하는 동안 서버가 실행되지 않도록 서비스 운영 절차에 따라 중지해야 합니다.

**새 행사:** 기존 기록을 백업한 뒤 `.env`의 `DATA_DIR`를 새 빈 폴더 경로(예: `./data-event-2`)로 바꾸고 재시작합니다. 기존 폴더는 그대로 남습니다. Render에서는 `/var/data/event-2`처럼 영구 디스크 아래의 새 경로를 사용하세요. 새 폴더도 GitHub 업로드에서 제외하세요.

매 변경 전 DB에 내부 스냅샷이 저장되지만, 이를 되돌리는 운영자 UI는 제공하지 않습니다. 대회 종료는 반드시 기록을 검토한 뒤 누르세요.

## 점검 및 문제 해결

- 테스트: `npm.cmd test` (Render/Linux는 `npm test`). 자동 테스트는 임시 DB를 사용하며 실제 경기 DB를 수정하지 않습니다.
- 로그인 오류: `HOST_PIN`이 8자 이상인지 확인합니다. 10회 실패하면 10분간 재시도가 제한됩니다.
- 재시작 후에는 다시 로그인해야 합니다. 경기 기록은 유지되지만 로그인 세션은 서버 메모리에 있어 초기화됩니다.
- 로컬 HTTP에서는 `NODE_ENV=development`를 사용합니다. `production`은 HTTPS 전용 로그인 쿠키를 사용합니다.
- 접속이 끊기면 화면의 마지막 데이터가 그대로 남고 빨간색 연결 안내가 표시됩니다. 연결이 복구되면 최신 상태를 다시 받습니다. **오프라인 상태에서 입력한 기록은 서버에 저장되지 않으므로 저장 완료를 확인하세요.**
- 다른 진행자 창에서 저장하면 기존 화면의 입력을 자동으로 덮어쓰지 않습니다. 충돌 안내가 나오면 내용을 확인한 뒤 최신 화면을 불러와 다시 입력하세요.
- 화면 주소를 `file://`로 직접 열지 말고 서버 주소로 접속하세요.
- DB는 단일 서버 인스턴스용입니다. 멀티 인스턴스 수평 확장은 지원하지 않습니다.

배포 기준은 2026-10-11 확인한 [Render Node 서비스 안내](https://render.com/docs/deploy-node-express-app), [영구 디스크 안내](https://render.com/docs/disks), [Blueprint 명세](https://render.com/docs/blueprint-spec)에 따릅니다.


## 자동차 이름

- 참가자 등록 시 `차량번호,이름,자동차이름` 형식으로 입력할 수 있습니다. 예: `1,김하늘,번개호`.
- 기존 `이름` 또는 `차량번호,이름` 형식도 지원하며 자동차 이름은 선택 입력입니다.
- 진행자 화면의 **자동차 이름 등록·수정**에서 참가자를 선택하고 이름을 저장합니다. 경기 시작 후에도 입력·수정할 수 있습니다.
- 최대 24자. TV 카드 아래쪽에서 잘 보이도록 짧은 이름을 권장합니다. 긴 이름은 말줄임 표시됩니다.
- 이름이 없으면 **자동차 이름 미등록**으로 표시됩니다. 기존 DB도 그대로 사용할 수 있습니다.
- 자동차 이름은 SQLite와 JSON/CSV 내보내기에 저장됩니다. 변경해도 주행 기록·편성은 바뀌지 않습니다.
